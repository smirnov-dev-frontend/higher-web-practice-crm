# CRM-платформа

Веб-приложение для управления взаимоотношениями с клиентами. Позволяет вести базу клиентов, отслеживать сделки на всех этапах воронки продаж, назначать задачи и просматривать аналитические отчёты по продажам и активности команды.

## Стек технологий

| Слой | Технологии |
|---|---|
| UI | React 19, TypeScript, CSS Modules |
| Маршрутизация | React Router v7 |
| Состояние | Redux Toolkit, RTK Query |
| Формы и валидация | react-hook-form, zod |
| Тестирование | Jest, React Testing Library |
| Сборка | Vite |
| Моковый API | json-server |

## Управление состоянием и данными

Приложение использует два уровня состояния:

**RTK Query** отвечает за серверные данные. Каждая сущность (клиенты, сделки, задачи, пользователи) описана набором эндпоинтов с `query` для чтения и `mutation` для записи. Теги (`providesTags` / `invalidatesTags`) обеспечивают автоматическую инвалидацию кэша: например, при создании новой сделки список сделок обновляется без ручного вызова.

**Redux Toolkit (authSlice)** хранит данные текущей сессии - авторизованного пользователя и флаг аутентификации. Состояние сессии сохраняется в `localStorage` через кастомный сериализатор, поэтому при перезагрузке страницы пользователь остаётся авторизованным.

## Формы и валидация

Все формы построены на связке `react-hook-form` + `zod`. Zod-схемы описывают контракт каждого поля централизованно: тип, обязательность, форматы и кастомные правила (например, проверка формата российского телефона или валидность URL сайта). Схемы вынесены в отдельные файлы (`clientsSchema.ts`, `dealSchema.ts`, `taskSchema.ts`) и могут использоваться независимо от компонентов - в том числе в unit-тестах.

Ошибки валидации отображаются под каждым полем. Обязательные поля помечены звёздочкой в лейбле. При редактировании существующей записи форма заполняется начальными данными через `reset()`.

## Маршрутизация и защита маршрутов

Роутер разделён на две группы: публичные маршруты (авторизация, регистрация, восстановление пароля) обёрнуты в `AuthLayout`, приватные - в `ProtectedRoute`, который проверяет наличие сессии и перенаправляет на `/login` при её отсутствии. Незнакомые маршруты (`*`) редиректят на главную страницу. Вложенные маршруты используют `Outlet` для рендера дочерних страниц внутри общего лейаута.

## UI-кит

Все базовые компоненты написаны самостоятельно без сторонних UI-библиотек:

- **Button** - поддерживает варианты `primary`, `secondary`, `danger`, `complete` и состояние `disabled`
- **Input** - обёртка над `<input>` с поддержкой `ref`, ошибок и состояния `disabled`
- **FormField** - контейнер с лейблом, звёздочкой обязательности и отображением ошибки
- **Modal** - портал с фокус-ловушкой, закрытием по `Escape` и клику на backdrop
- **Select** - кастомный дропдаун с позиционированием через `getBoundingClientRect`
- **Combobox** - Select с поиском по опциям
- **ColumnFilter** - заголовок таблицы с сортировкой и мульти-фильтрацией

## Функциональность страниц

- **Главная (Dashboard)** - сводная статистика по клиентам и сделкам, 10 активных клиентов, последние сделки и задачи, кнопки быстрого перехода к созданию записей
- **Клиенты** - таблица с сортировкой и фильтрацией по всем полям, модальное окно создания и редактирования, мягкое удаление (клиент помечается удалённым, его сделки сохраняются)
- **Сделки** - статусы Новая / В работе / Завершена / Отменена, завершённые сделки переходят в режим просмотра с зелёным фоном
- **Задачи** - автоматическое определение просрочки (срок прошёл, задача не завершена), смена статуса заблокирована для просроченных задач до изменения срока
- **Отчёты** - три вкладки: по продажам (с разбивкой по этапам сделок), по клиентам (новые и активность), по задачам (активные и просроченные); фильтрация по периоду, сортировка по любому полю, постраничная навигация, экспорт в PDF и XLSX
- **Профиль** - смена имени, email с демо-верификацией через код, пароля с подтверждением текущего, загрузка аватара

## Запуск проекта

### Установка зависимостей

```bash
npm install
```

### Моковый бэкенд (json-server)

Запустите в отдельном терминале - необходимо перед стартом фронтенда:

```bash
npm run server
```

Сервер поднимается на порту `3001`.

### Фронтенд

```bash
npm run dev
```

Приложение доступно по адресу из вывода команды (обычно `http://localhost:5173`).

### Сборка для продакшена

```bash
npm run build
```

### Линтинг

```bash
npm run lint
```

### Тесты

```bash
npm test
```
